## Введение

**Redis Commander TUI** - терминальный интерфейс для работы с Redis Standalone и Redis Cluster. Приложение позволяет подключаться к нескольким серверам, переключать базы данных, просматривать ключи, редактировать значения, выполнять команды Redis и работать с профилями подключения из обычного JSON, зашифрованного файла или HashiCorp Vault.

### Что умеет текущая версия

- Подключение к **Redis Standalone** и **Redis Cluster**
- Несколько профилей подключения в одном конфигурационном файле
- Переключение между **DB0-DB15** в standalone режиме
- Просмотр списка ключей с определением типа
- Фильтрация и массовая отметка ключей по glob-шаблонам
- Добавление и редактирование ключей типов `string`, `hash`, `list`, `set`, `zset`, `bitmap`, `stream`
- Удаление одного ключа из панели деталей и массовое удаление отмеченных ключей
- Встроенная Redis-консоль с историей команд и специальной обработкой cluster-команд
- Поддержка TLS/SSL, Unix socket, encrypted config и HashiCorp Vault
- Аудит-лог в `redis_tui_audit.log`

### Архитектурные диаграммы

PlantUML-исходники для текущей реализации находятся в каталоге `diagramms/`:

- `diagramms/architecture-overview.puml`
- `diagramms/startup-and-profile-loading.puml`
- `diagramms/ui-key-workflow.puml`
- `diagramms/cluster-scan-and-console.puml`

Для каждой диаграммы также есть русская копия с суффиксом `-ru`.

### Важные ограничения текущей реализации

- При сканировании загружается не более **5000 ключей** на текущую базу/кластер
- Панель деталей полноценно показывает значения для `string`, `hash`, `list`, `set`, `zset`
- Для `bitmap`, `stream` и других нестандартных типов в панели деталей отображается только общий тип без расшифровки содержимого
- Для `list`, `set` и `zset` в панели деталей показываются только первые **100 элементов**
- Флаг профиля `readonly` не является жесткой защитой от записи: он скрывает кнопку `Delete Key` в панели деталей, но не блокирует операции записи через диалоги добавления/редактирования и консоль. Для реальной защиты используйте ACL/права на стороне Redis

## Установка и запуск

### Требования

- Python 3.7+
- `urwid`
- модуль `simple_redis_client`, используемый приложением
- `cryptography` для зашифрованных конфигураций
- `hvac` для режима HashiCorp Vault

Пример установки Python-зависимостей:

```bash
pip install urwid cryptography hvac
```

### Файлы проекта

- Основной исполняемый файл: `redis-commander.py`
- Скрипт шифрования конфигурации: `config-encryptor.py`
- Конфигурация по умолчанию: `redis_profiles.json`

### Режимы запуска

#### Режим 1: обычный JSON-файл

```bash
python redis-commander.py
# или
python redis-commander.py -c redis_profiles.json
```

Если файл конфигурации не найден или пуст, приложение создаст временный профиль `localhost:6379`.

#### Режим 2: зашифрованный конфиг

```bash
python redis-commander.py -e redis_profiles.enc
```

При запуске приложение запросит пароль для расшифровки.

#### Режим 3: HashiCorp Vault

```bash
python redis-commander.py \
  --vault-url https://vault.example.com:8200 \
  --vault-path secret/data/redis-commander \
  --vault-user redis-admin
```

Если `--vault-user` или `--vault-pass` не указаны, приложение запросит их интерактивно.

### Параметры командной строки

| Параметр | Назначение |
|----------|------------|
| `-c`, `--config` | путь к plaintext JSON-конфигу, по умолчанию `redis_profiles.json` |
| `-e`, `--encrypted-config` | путь к зашифрованному конфигу |
| `--vault-url` | URL HashiCorp Vault |
| `--vault-path` | путь к секрету в Vault |
| `--vault-user` | имя пользователя Vault |
| `--vault-pass` | пароль Vault; передача в командной строке небезопасна |

## Конфигурация подключений

### Базовый формат `redis_profiles.json`

```json
{
  "my-local": {
    "name": "my-local",
    "host": "127.0.0.1",
    "port": 6379,
    "cluster_mode": false
  },
  "my-cluster": {
    "name": "my-cluster",
    "host": "127.0.0.1",
    "port": 7000,
    "cluster_mode": true,
    "cluster_nodes": [
      ["127.0.0.1", 7000],
      ["127.0.0.1", 7001],
      ["127.0.0.1", 7002]
    ]
  }
}
```

### Поддерживаемые параметры профиля

| Параметр | Тип | Описание |
|----------|-----|----------|
| `name` | string | отображаемое имя профиля; если параметр пропущен, используйте понятное имя записи верхнего уровня |
| `host` | string | хост Redis |
| `port` | integer | порт Redis |
| `password` | string/null | пароль |
| `username` | string/null | пользователь Redis 6+ |
| `ssl` | boolean | включить TLS/SSL |
| `ssl_ca_certs` | string | путь к CA-сертификату |
| `ssl_certfile` | string | путь к клиентскому сертификату |
| `ssl_keyfile` | string | путь к клиентскому ключу |
| `socket_path` | string | путь к Unix socket |
| `readonly` | boolean | режим "безопасного просмотра" на уровне UI |
| `cluster_mode` | boolean | подключение к Redis Cluster |
| `cluster_nodes` | array | список узлов кластера |

### Допустимые форматы `cluster_nodes`

Приложение принимает несколько вариантов описания узлов:

```json
{
  "cluster_nodes": [
    ["redis-1", 7000],
    "redis-2:7001",
    {"host": "redis-3", "port": 7002}
  ]
}
```

Если `host` и `port` не указаны, для первого подключения будет использован первый узел из `cluster_nodes`.

### TLS/SSL пример

```json
{
  "prod-tls": {
    "name": "prod-tls",
    "host": "redis.example.com",
    "port": 6380,
    "ssl": true,
    "ssl_ca_certs": "/path/to/ca.pem",
    "ssl_certfile": "/path/to/client-cert.pem",
    "ssl_keyfile": "/path/to/client-key.pem"
  }
}
```

### Unix socket пример

```json
{
  "local-socket": {
    "name": "local-socket",
    "socket_path": "/var/run/redis/redis.sock",
    "cluster_mode": false
  }
}
```

### Создание зашифрованной конфигурации

Используйте штатный скрипт проекта:

```bash
python config-encryptor.py redis_profiles.json redis_profiles.enc
```

Скрипт:

- проверяет, что входной файл является валидным JSON
- дважды запрашивает пароль
- сохраняет результат как `salt + encrypted_data`

## Интерфейс пользователя

### Общая схема экрана

- Верхняя строка: заголовок приложения
- Панель кнопок: `F1`, `F2`, `F3`, `F4`, `F8`, `F9`, `F10`, `F11`
- Левая область:
  - сверху дерево подключений и баз данных
  - снизу список ключей
- Правая область: детали выбранного ключа
- Нижняя строка: статус
- При включенной консоли появляется отдельная нижняя панель с историей и строкой ввода

### Левая панель

Левая часть экрана объединяет два блока:

1. Список профилей подключения
2. Список баз данных и ключей текущего подключения

Индикаторы:

- `●` - подключение активно
- `○` - профиль не подключен
- `▪` - активная база данных
- `▫` - неактивная база данных
- `[St]` - `string`
- `[Hs]` - `hash`
- `[Li]` - `list`
- `[Se]` - `set`
- `[Zs]` - `zset`
- `[Tr]` - `stream`
- `✓` перед иконкой типа - ключ отмечен для массовой операции

### Правая панель

Для выбранного ключа выводятся:

- имя ключа
- тип
- TTL
- размер/длина/количество элементов, если тип поддерживает такую метрику
- для кластера: `Hash Slot` и нода, на которой находится ключ
- значение ключа или сообщение об ограничении отображения

### Консоль

Консоль открывается в нижней части экрана и содержит:

- историю команд и результатов
- строку ввода `redis>`
- отдельный фокус, доступный по `Tab`

## Работа с ключами

### Выбор подключения и базы данных

1. Выберите профиль в дереве подключений
2. Для standalone выберите `DB0`-`DB15`
3. Для Redis Cluster доступна только `DB0`
4. После выбора приложение автоматически пересканирует ключи

### Сканирование и просмотр

- Список строится через `SCAN`, а не через блокирующий `KEYS`
- Для каждого найденного ключа определяется тип
- После выбора ключа нажмите `Enter`, чтобы открыть его детали
- При сканировании больших баз приложение останавливается после 5000 ключей

### Добавление нового ключа

**Клавиша: `F3`**

Доступные типы:

- `string`
- `hash`
- `list`
- `set`
- `zset`
- `bitmap`
- `stream`

Форматы ввода:

**String**

```text
Любой текст
Многострочный ввод будет сохранен как строка с \n
```

**Hash**

```text
field1:value1
field2:value2
```

**List**

```text
item1
item2
item3
```

**Set**

```text
member1
member2
member3
```

**ZSet**

```text
member1:1.0
member2:2.5
member3:10
```

**Bitmap**

```text
0:1
1:0
100:1
```

**Stream**

```text
field1:value1
field2:value2
```

Дополнительно можно указать `TTL` в секундах.

### Редактирование ключа

**Клавиша: `F4`**

Поведение:

- для `string`, `hash`, `list`, `set`, `zset` существующее значение предварительно подгружается в форму
- при смене типа старый ключ удаляется и создается заново
- для `bitmap` и `stream` текущая реализация не подгружает содержимое автоматически, поэтому такие значения нужно вводить вручную

Сохранение и отмена:

- `F7` - сохранить
- `Esc` - закрыть форму

### Удаление ключей

#### Удаление одного ключа

1. Откройте ключ в панели деталей
2. Нажмите кнопку `Delete Key`
3. Подтвердите удаление

#### Массовое удаление

1. Отметьте ключи пробелом или по шаблону
2. Нажмите `F8`
3. Подтвердите удаление

### Отметка и фильтрация

**Фильтр списка**

- клавиша `/`
- поддерживаются glob-шаблоны `*` и `?`
- фильтр применяется только к уже загруженному списку ключей

Примеры:

```text
user:*
*session*
temp:?123
```

**Массовая отметка**

- `Space` - отметить или снять отметку с текущего ключа
- `Ctrl+A` - отметить ключи по шаблону
- `Ctrl+U` - снять все отметки

### Особенности Redis Cluster

- база данных всегда `DB0`
- для multi-key операций Redis требует один hash slot
- если вы сознательно используете hash tags, задавайте ключи в формате `{tag}:suffix`

## Консоль Redis

### Открытие консоли

**Клавиша: `F2`**

После открытия:

- верхняя часть интерфейса остается доступной
- внизу появляется панель консоли
- фокус переводится на строку ввода

### Базовое использование

```text
redis> SET mykey "Hello"
OK

redis> GET mykey
"Hello"

redis> HGETALL user:1001
1) "name" => "John Doe"
2) "email" => "john@example.com"
```

### История команд

- `Page Up` или `Ctrl+P` - предыдущая команда
- `Page Down` или `Ctrl+N` - следующая команда
- история сохраняется в `~/.redis_commander_history`
- между запусками сохраняются последние **100 команд**

### Специальные команды консоли

- `exit` или `quit` - закрыть консоль
- `clear` - очистить экран консоли

### Автообновление после изменений

После модифицирующих команд список ключей автоматически обновляется. Это касается, например:

- `SET`, `DEL`, `HSET`, `LPUSH`, `SADD`, `ZADD`
- `EXPIRE`, `PERSIST`, `RENAME`
- `FLUSHDB`, `FLUSHALL`

### Cluster-aware поведение консоли

В cluster режиме консоль обрабатывает ряд команд специально:

- `KEYS <pattern>` - собирает ключи со всех master-нод
- `SCAN ...` - сканирует все master-узлы и объединяет результат
- `INFO [section]` - может собирать информацию по master-нодам
- `DBSIZE` - суммирует размер по master-нодам
- `FLUSHDB`, `FLUSHALL` - выполняет команду на всех master-нодах
- `CLUSTER ...` - отправляет команду через cluster client

В cluster режиме помечаются как неподдерживаемые:

- `SELECT`
- `MOVE`
- `SWAPDB`
- `MIGRATE`
- `RANDOMKEY`

При ошибках `CROSSSLOT` и `MOVED` приложение выводит отдельные сообщения в консоль.

## Режимы безопасности

### Режим 1: plaintext JSON

```bash
python redis-commander.py -c redis_profiles.json
```

Когда подходит:

- локальная разработка
- тестовые окружения
- временные конфиги без секретов

Минусы:

- пароли хранятся в открытом виде

### Режим 2: encrypted config

Создание:

```bash
python config-encryptor.py redis_profiles.json redis_profiles.enc
```

Использование:

```bash
python redis-commander.py -e redis_profiles.enc
```

Особенности:

- используется `PBKDF2-HMAC-SHA256`
- соль хранится в первых 16 байтах файла
- расшифровка происходит по паролю при запуске

### Режим 3: HashiCorp Vault

Использование:

```bash
python redis-commander.py \
  --vault-url https://vault.company.com:8200 \
  --vault-path secret/data/redis-commander \
  --vault-user redis-admin
```

Ожидания к содержимому секрета:

- секрет должен содержать объект с профилями в том же формате, что и `redis_profiles.json`
- приложение читает данные как KV v2

### Режим `readonly`

Параметр профиля:

```json
{
  "readonly": true
}
```

Что дает в текущей версии:

- скрывает кнопку `Delete Key` в панели деталей

Что не дает:

- не блокирует `F3` и `F4`
- не блокирует команды записи в консоли

Для реального read-only доступа используйте Redis ACL или отдельного пользователя с ограниченными правами.

## FAQ и ограничения

### Есть ли ограничение по числу ключей?

Да. Список ключей ограничен **5000 элементами** на одно сканирование для сохранения отзывчивости интерфейса.

### Что происходит, если конфиг отсутствует?

Если JSON-файл не найден, приложение стартует с временным профилем `localhost:6379`.

### Можно ли работать с бинарными значениями?

Да, но только частично:

- бинарные строки и поля отображаются как `<binary data: N bytes>` или `<binary: N bytes>`
- редактирование бинарных значений в удобном специализированном виде не реализовано

### Как переключаться между базами данных?

- в standalone режиме доступны `DB0-DB15`
- в cluster режиме доступна только `DB0`

### Как лучше работать с multi-key командами в кластере?

Используйте ключи с одним hash tag:

```text
{user:42}:profile
{user:42}:settings
```

Это увеличивает шанс, что multi-key операции не закончатся ошибкой `CROSSSLOT`.

### Полностью ли поддерживаются `bitmap` и `stream`?

Нет, поддержка частичная:

- создать и сохранить такие ключи через диалог можно
- редактирование существующих значений неудобно, потому что форма не подгружает текущее содержимое
- панель деталей не показывает содержимое этих типов в расшифрованном виде

### Где хранится история команд?

В файле:

```text
~/.redis_commander_history
```

После каждого обновления сохраняются последние **100 команд**.

## Логи и диагностика

### Audit log

Все основные действия пишутся в файл:

```text
redis_tui_audit.log
```

Там фиксируются:

- подключения и отключения
- выполненные Redis-команды
- ошибки сканирования, загрузки и редактирования

### Диагностика кластера

Горячая клавиша `F12` показывает в панели деталей отладочную информацию по cluster client:

- доступные методы клиента
- сведения о нодах
- результат `CLUSTER INFO`, если его удалось получить
